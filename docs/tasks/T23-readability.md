# T23 — Make the decompiled code readable (names, registers, structs, libraries)

**Status:** in progress (2026-10-29) · **Depends on:** T10, T11, T12, T17, T21 · **Issue:** (created by `tools/issues_sync.py`)

## Goal
Turn `decomp/` from "decompiled" into "readable": every peripheral register printed by name, the big state blocks typed as
structs, library code recognised by signature, the most-called functions named, and the progress measured so anyone can
see how far it has got. Each step is a committed table plus a script, so it can be **redone** when Yaesu ships new
firmware or when someone learns more (see [Redo](#redo-new-firmware-or-new-information)).

The progress figures (decompiled, named, documented, calls named, registers named) are generated by
`tools/readability_stats.py` into the block at the top of [README.md](../../README.md). `site/build.py` copies that block
to the top of the website and `tools/guide_to_wiki.py` to the top of the wiki's Home page.

Order: T23a and T23b first (mechanical, largest gain per hour), then T23c (the real gain in readability; register names make
field accesses easier to recognise), then T23d, T23e and T23f, which feed each other. T23g last.

Rules for every sub-task:
- The source of truth is a committed TSV (or header) plus a script that applies it; the Ghidra project only holds the
  result. Never name things by hand in the GUI without writing them to the TSV.
- Generated tables carry a header that says what made them and from which input; never edit them by hand.
- After a Ghidra apply: re-export `decomp/<image>/` with `ExportDecomp.java`, run `tools/decomp_quality.py compare`
  (no count may get worse), run `python3 -I tools/readability_stats.py readme`, and commit the Ghidra project, the
  re-export and the README together (AGENTS.md).
- Mark every name with how it was found: names from the manual are [fact]; names from code behaviour are [inference].

## Redo (new firmware or new information)

**A new MAIN firmware** (V01-13 or later):
1. Decode it (`tools/bootstrap.sh --only inputs,decode` after updating `docs/inputs.sha256`) and rebuild the project.
   `build_main` in `tools/bootstrap.sh` must run `ApplySfr.java` after `ApplySignatures.java` (open step T23a-3 below).
2. `python3 -I tools/sfr_table.py coverage decomp/main` after the re-export: any `missing:` address is a register the
   new code uses that the table lacks. Look it up in the manual and add it to `EXTRA` in `tools/sfr_table.py` with its
   source, then rebuild the TSV.
3. Re-run the struct, signature and name steps (T23c–T23f) through their TSVs; addresses of functions move between
   versions, so port names with a function matcher (Ghidra Version Tracking or BSim against the old program) rather than
   by address. Record the port in this file.

**A new manual revision** (RX651 HWM after Rev.2.40): put the PDF in `Manuals/Renesas/`, run
`python3 -I tools/sfr_table.py build --pdf <new.pdf>`, review the TSV diff (the built-in checks must pass), and re-apply.

**New information about a register** (for example a register that Table 5.1 omits): add a sourced row to `EXTRA` in
`tools/sfr_table.py`, rebuild, re-apply.

**Progress figures**: `python3 -I tools/readability_stats.py readme` after any change to `decomp/` or `docs/code/`;
`check` exits 1 when the README is stale. `tools/bootstrap.sh --only export` runs `readme` itself.

## T23a — MAIN: RX651 peripheral-register names

**Status:** table and script done (2026-10-29); the Ghidra steps are open (owner: hold off on Ghidra).

### Findings
- Before this task the MAIN export printed every peripheral register as an address: **2,216 references at 591 I/O
  addresses** in `decomp/main`, for example `DAT_00088032 = 0x3350` in `R_IWDT_Create` (that is `IWDT.IWDTCR`) **[fact]**.
- Source: Table 5.1 "List of I/O Registers (Address Order)" of the committed RX65N/RX651 hardware manual
  (`Manuals/Renesas/r01uh0590ej0240-rx651.pdf`, Rev.2.40, PDF pages 193–245, 53 table pages; pdftotext 24.02.0).
  `tools/sfr_table.py build` rebuilds the rows that `pdftotext -layout` splits (wrapped names, symbols on a second line,
  three forms of address ranges, including the GLCDC rows whose end address is the last register's start) and expands
  every range. Output `tools/ghidra/sfr_rx651.tsv`: **4,776 registers at 4,642 addresses in 131 modules**, 0 unparsed
  rows; the build is deterministic **[fact]**.
- Checks built into the script: 18 known registers at known addresses (from the manual chapters and `docs/code/main`),
  no label at two addresses, widths 8/16/32/64/128, 16- and 32-bit primary registers aligned, more than 2,000 rows.
- 124 addresses carry more than one register (134 alias rows: other modes of one register: `SMCI0_SMR` next to `SCI0_SMR`;
  `TMR01_TCORA` 16-bit over `TMR0_TCORA`/`TMR1_TCORA`); 138 rows overlap with a different start or width. The TSV marks
  them (`primary`, `overlap`), and `ApplySfr.java` only labels the overlapping ones and types the rest.
- Coverage before Ghidra (`tools/sfr_table.py coverage`): **2,211 of the 2,216 references (99.8 %)** fall on a register
  in the table. The five left are `DAT_000f4240`, which is the constant 1,000,000 that Ghidra typed as a pointer
  parameter of `FUN_fff8fc57` (a T23f signature fix, not a register) **[fact]**.
- Five registers the firmware uses are not in Table 5.1 and are in the `EXTRA` list:
  - `ICU_IER00`/`IER01` at 0x87200: reserved in the table, but `FUN_fff8ff82` and `FUN_fff8ffa3` index
    `(&DAT_00087200)[vector >> 3]` and set or clear bit `vector & 7`, so they are the IER base, and those two functions
    are **interrupt enable/disable by vector number** (names for T23e) **[inference]**.
  - `DBG_C2E0`/`DBG_E2C0`/`DBG_DBGSTAT` at 0x84080/0x84090/0x840C0: polled on bit 8 before a write and on bit 12 before
    a read, in `FUN_fff8f8bb` (write) and `FUN_fff8f8d8` (read) just before `_INIT_IOLIB` @ 0xFFF8F8F5. This matches the E1/E2 emulator virtual-console port that the
    Renesas BSP's low-level I/O (`lowlvl.c` charput/charget) uses **[inference]**; the C library's stdio goes there.
- The option-setting memory registers (OFSM, at 0xFE7F5D00..) are in the TSV but outside the memory that
  `SetupRX651.java` maps, so `ApplySfr.java` skips them; MAIN does not reference them.
- `ApplySfr.java` adds labels with source IMPORTED, so names from `names_main.tsv` (USER_DEFINED) keep priority; it only
  replaces undefined data, and it is idempotent. **It has not been run yet.**
- Baseline in the README progress block: MAIN registers named **0.0 %**; after the apply it should read about 99.8 %.

- The M33 kernel is FreeRTOS **V10.3.x** [fact]: no FPU context save in `PendSV_Handler` (configENABLE_FPU 0), non-indexed task

  and the `ARM_CM33_NTZ` port; V10.3.0 and `V10.3.1-kernel-only` match identically, V10.2.1 matches 33 functions instead of 67.
  The build is `-Os` (67 matches vs 22 at `-O1`, 15 at `-O2`).
- Four more hand-named kernel functions agree with the source but fall under the uniqueness margin (`prvInsertBlockIntoFreeList`,

- Redlib (NXP's closed C library), the MCUXpresso drivers and rpmsg-lite were not compiled: their M33 functions already
